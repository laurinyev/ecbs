# TODOZilla
TODOZilla is an experimental tool for managing markings like TODOs, BUGs, HACKs and the like.

## TZ.yml
TZ.yml is the configuration file for TODOZilla.

### comment_formats
* TODOZilla knows what files to search and how to track comments through this array.
* Each element is an associative array with keys: 
    - `ext` for the file extension, 
    - `nlt_start` for the start pattern of signle-line comments, 
    - `block_start` for the start pattern of block comments and
    - `block_end` for the end pattern of block comments.

### categories
* Categories are the strings like "BUG" or "HACK HACK" TODOZilla looks for in the source file.  
* Each element is a valid marking string.

### domains
* Optional.
* Domains is a key-value array assigning names to file/directory paths.
* They are used for the auto-generation.
* Providing this value enables Domains.

### nesting_hierarchy
* Optional.
* A string of 1-3 characters containing the characters `d` for domain, `f` for file and `c` for category once.
* It is used for determining the heading hierarchy for Code Markings.
* Default value is `dfc`.

### base_dir
* Optional.
* Specifies the base directory TODOZilla works on.
* Default value is "."

### markings_heading
* Optional.
* Specifies the name of the Code Markings heading.
* Default value is "Code Markings".

### ephemeral_heading
* Optional.
* Specifies the name of the Ephemeral TODO heading.
* Providing this value enables Ephemeral TODOs.

## TZ.md
* TZ.md contains the actual TODOs, BUGs as well as whatever the user wants.

### Code Markings
* Its name is defined by `markings_heading`,
    - `Code Markings` being the default.
* This heading is generated by TODOZilla.
    - Contains markings found in the code.
* Hierarchical strucure defined by `nesting_hierarchy`.

### "Ephemeral TODOs" heading
* Its name is defined by `ephemeral_heading`.
    - The absence of the `ephemeral_heading` option marks this feature as disabled.
* This heading's can be emptied or excluded from staged git changes.

## "todozilla" cli utility
* The utility has several subcommands.
* All subcommands except `todozilla init` error out if TZ.yml is not found or invalid. 
* The exit code is the error code or `0` or success.

### "todozilla init" subcommand
* Prompts whether to enable Ephemeral TODOs.
* Prompts whether to automatically set up a git pre-commit hook.
* Prompts for the names of the headings.
    - Only prompts for the name of  Ephemeral TODOs if it was enabled.
    - Default name for Ephemeral TODOs if enabled is `Ephemeral TODOs`. 
* Creates a sample TZ.md file with the following content:
    - `# <markings_heading>` is always inserted,
    - `# <ephemeral_heading>` only if it was enabled.
* Creates a sample TZ.yml file with the following content:
    - `comment_formats` containing an example entry for yml.
    - `categories` containing `TODO`, `BUG` and `HACK`.
    - `markings_heading` being filled only if the name given differs from the default.
    - `ephemeral_heading` being filled if the feature was enabled.
    - everything else is omitted.
* Creates the git pre-commit hook
    - if the user selected the option.
    - if the script already exists, it only appends to it.
    - the default script runs `todozilla regen` and `todozilla exclude`

### "todozilla regen" subcommand
* Scans files and regenerates the Code Markings heading.
* Errors out if the heading is not found.

### "todozilla empty" subcommand
* Empties the Ephemeral TODOs section.
* Errors out if feature is not enabled or the heading is not found.

### "todozilla exclude" subcommand
* Excludes the Ephemeral TODOs section from staged git changes.
* Errors out if feature is not enabled or the heading is not found.
