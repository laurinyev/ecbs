# TODOZilla
TODOZilla is an experimental tool for managing markings like TODOs, BUGs, HACKs and the like.

## Markings
* Markings are the things TODOZilla tracks.
* A marking is either unannotated or annotated.
* An unannotated marking consists only of the category name. Any other text following it in the comment is not part of the marking.
* An annotated marking consists of the category name immediately followed by a colon (`:`).
    - The annotation starts after the colon.
    - Leading and trailing whitespace is not part of the annotation.
    - The annotation ends before the first unmatched closing parenthesis (`)`), curly brace (`}`) or square bracket (`]`), or at the end of the comment.
    - A closing delimiter is unmatched when there is no earlier unclosed opening delimiter of the same kind within the annotation. Balanced delimiters are part of the annotation.


## TZ.yml
TZ.yml is the configuration file for TODOZilla.

### comment_formats
* TODOZilla knows what files to search and how to track comments through this array.
* Each element is an associative array with keys:
    - `ext` for the file extension,
    - `nlt_start` for the start pattern of single-line comments,
    - `block_start` for the start pattern of block comments and
    - `block_end` for the end pattern of block comments.
* Comment patterns are matched literally; they are not regular expressions.
* Single-line comments run from `nlt_start` to the end of the line.
* Block comments run from `block_start` to `block_end` and may span multiple lines.
* Only text inside comments is searched for markings.
* An extension may be written with or without a leading dot and is matched case-insensitively.
* A comment format must define both `block_start` and `block_end`, or neither of them.

### categories
* Categories are the strings like "BUG" or "HACK HACK" TODOZilla looks for in the source file.
* Each element is a valid marking string.
* Category matching is case-sensitive and exact.
* A category only matches when it is not adjacent to a letter, digit or underscore.

### domains
* Optional.
* Domains is a key-value array assigning names to file/directory paths.
* They are used for the auto-generation.
* Providing this value enables Domains.
* Domain paths are relative to `base_dir`.
* A file belongs to a domain when its path equals the domain path or lies beneath it.
* When multiple domains match, the most specific (longest) path wins.
* Files that belong to no configured domain have no domain heading.

### nesting_hierarchy
* Optional.
* A string of 1-3 characters containing the characters `d` for domain, `f` for file and `c` for category once.
* It is used for determining the heading hierarchy for Code Markings.
* Default value is `fdc`.

### base_dir
* Optional.
* Specifies the base directory TODOZilla works on.
* Default value is "."
* Files with a configured extension anywhere beneath `base_dir` are searched.
* The `.git` directory is ignored, symlinks are not followed, and files that cannot be read as UTF-8 are ignored.
* File paths in generated headings and output are relative to `base_dir` and use forward slashes.

### markings_heading
* Optional.
* Specifies the name of the Code Markings heading.
* Default value is "Code Markings".

### ephemeral_heading
* Optional.
* Specifies the name of the Ephemeral TODO heading.
* Providing this value enables Ephemeral TODOs.

## TZ.md
* TZ.md contains the actual TODOs, BUGs as well as whatever the user wants.

### Code Markings
* Its name is defined by `markings_heading`,
    - `Code Markings` being the default.
* This heading is generated by TODOZilla.
    - Contains markings found in the code.
* Hierarchical structure is defined by `nesting_hierarchy`.
* The Code Markings section starts after its heading and ends before the next ATX heading of the same or higher level, or at the end of the file.
* The heading line itself is preserved; content outside the section is left untouched.
* Generated headings start one heading level below the Code Markings heading.
* For each character in `nesting_hierarchy`:
    - `d` generates a heading named after the domain,
    - `f` generates a heading named after the file path relative to `base_dir`,
    - `c` generates a heading named after the category.
* A dimension with no value is omitted. Its lower dimensions then start one heading level higher.
* Markings are ordered by domain name, file path, configured category order and line number.
* Each marking is emitted as a list item:
    - `- <text> (line <number>)` when a file heading is used,
    - `- <text> (<path>:<line>)` when there is no file heading,
    - `**[<CATEGORY>]** ` is prepended to `<text>` when there is no category heading.
* For an annotated marking, `<text>` is the annotation.
* For an unannotated marking, `<text>` is the category name.
* An empty Code Markings section consists only of its heading.

### "Ephemeral TODOs" heading
* Its name is defined by `ephemeral_heading`.
    - The absence of the `ephemeral_heading` option marks this feature as disabled.
* This heading's content can be emptied or excluded from staged git changes.
* The Ephemeral TODOs section starts after its heading and ends before the next ATX heading of the same or higher level, or at the end of the file.
* Emptied Ephemeral TODOs consist only of the heading.

## "todozilla" cli utility
* The utility has several subcommands.
* All subcommands except `todozilla init` error out if TZ.yml is not found or invalid. 
* The exit code is the error code or `0` or success.

### "todozilla init" subcommand
* Prompts whether to enable Ephemeral TODOs.
* Prompts whether to automatically set up a git pre-commit hook.
* Prompts for the names of the headings.
    - Only prompts for the name of  Ephemeral TODOs if it was enabled.
    - Default name for Ephemeral TODOs if enabled is `Ephemeral TODOs`. 
* Creates a sample TZ.md file with the following content:
    - `# <markings_heading>` is always inserted,
    - `# <ephemeral_heading>` only if it was enabled.
* Creates a sample TZ.yml file with the following content:
    - `comment_formats` containing an example entry for yml.
    - `categories` containing `TODO`, `BUG` and `HACK`.
    - `markings_heading` being filled only if the name given differs from the default.
    - `ephemeral_heading` being filled if the feature was enabled.
    - everything else is omitted.
* The sample yml comment format is an `ext` of `yml` with `nlt_start` set to `#`.
* Creates the git pre-commit hook
    - if the user selected the option.
    - if the script already exists, it only appends to it.
    - the default script has the following content:

```
#!/bin/sh
todozilla regen
todozilla exclude
```

### "todozilla regen" subcommand
* Scans files and regenerates the Code Markings heading.
* Errors out if the heading is not found.

### "todozilla empty" subcommand
* Empties the Ephemeral TODOs section.
* Errors out if feature is not enabled or the heading is not found.

### "todozilla exclude" subcommand
* Excludes the Ephemeral TODOs section from staged git changes.
* Errors out if feature is not enabled or the heading is not found.

### Errors
* Runtime errors are written to stderr in the form:
  `todozilla: error[TZnnn NAME]: <message>`
  followed by zero or more `  caused by: <message>` lines for underlying failures.
* The process exits with the numeric part of the error tag (`nnn`).
* Successful commands exit with `0`. CLI usage errors are handled by the argument parser and exit with `2`.

| Exit | Tag | Name | Reported when |
| ---: | --- | --- | --- |
| 1 | TZ001 | INTERNAL | An unexpected internal failure occurs. |
| 2 | TZ002 | IO | Reading from or writing to the terminal fails. |
| 10 | TZ010 | CONFIG_NOT_FOUND | `TZ.yml` does not exist. |
| 11 | TZ011 | CONFIG_UNREADABLE | `TZ.yml` exists but cannot be read. |
| 12 | TZ012 | CONFIG_INVALID | `TZ.yml` cannot be parsed or fails validation. |
| 13 | TZ013 | CONFIG_WRITE_FAILED | `TZ.yml` cannot be written by `init`. |
| 20 | TZ020 | MARKDOWN_NOT_FOUND | `TZ.md` does not exist. |
| 21 | TZ021 | MARKDOWN_UNREADABLE | `TZ.md` exists but cannot be read. |
| 22 | TZ022 | MARKDOWN_WRITE_FAILED | `TZ.md` cannot be written. |
| 23 | TZ023 | MARKINGS_HEADING_NOT_FOUND | The Code Markings heading is missing from `TZ.md`. |
| 24 | TZ024 | EPHEMERAL_HEADING_NOT_FOUND | The Ephemeral TODOs heading is missing from `TZ.md`. |
| 25 | TZ025 | EPHEMERAL_DISABLED | The command needs Ephemeral TODOs, but `ephemeral_heading` is not configured. |
| 30 | TZ030 | BASE_DIR_NOT_FOUND | The configured `base_dir` does not exist. |
| 31 | TZ031 | DIRECTORY_WALK_FAILED | The source tree cannot be traversed. |
| 40 | TZ040 | GIT_REPOSITORY_NOT_FOUND | A git repository cannot be found. |
| 41 | TZ041 | GIT_COMMAND_FAILED | A git command cannot be run or fails unexpectedly. |
| 42 | TZ042 | GIT_INDEX_UPDATE_FAILED | Updating the git index fails in `exclude`. |
| 43 | TZ043 | HOOK_WRITE_FAILED | The git pre-commit hook cannot be created or updated. |

#### CONFIG_INVALID sub-errors
`TZ012` has one shared code. Its message identifies the specific problem:

* YAML cannot be parsed, has the wrong value type, or is missing the required `comment_formats` or `categories` keys.
* `comment_formats` contains a format with an empty `ext`.
* A comment format defines only one of `block_start` and `block_end`.
* A comment format defines an empty `nlt_start`, `block_start` or `block_end` pattern.
* `categories` is empty or contains an empty category string.
* `nesting_hierarchy` is empty, is longer than three characters, contains a character other than `d`, `f` or `c`, or repeats one of them.
* `markings_heading` or `ephemeral_heading` is present but empty.
